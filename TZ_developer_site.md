# ТЗ: сайт разработчика на GitHub Pages

## 1. Задача

Сделай статический сайт разработчика для GitHub Pages. Это витрина: кто я, что я выпустил, куда нажать, чтобы скачать или открыть. На сайте мои приложения, сайты и игры. Сегодня в наличии два приложения и один сайт, игры появятся позже, поэтому проекты хранятся в данных, а не вшиты в вёрстку.

Один посетитель, одна цель: открыть мой проект в магазине или на сайте. Главное действие на странице одно: «Смотреть проекты».

## 2. Что прочитать до первой строки кода

В репозитории лежат два файла (если нет, положи их в `/skills`):

- `SKILL.md` (landing-page-design): структура страницы, копирайт и жёсткая визуальная система. Это основа.
- `SKILL_motion.md` (design-to-motion): правила анимации. Нужен только раздел про веб (см. п. 7).

Приоритет при конфликте: это ТЗ → `SKILL.md` → `SKILL_motion.md`.

### Что из SKILL.md не применяем (это витрина, не продающий лендинг)

- FAQ, блок снятия рисков, отзывы и логотипы клиентов: ничего этого у меня нет, выдумывать запрещено.
- Страницу Terms и cookie баннер: сайт не собирает данные. Нужна только короткая страница политики конфиденциальности.
- Форму с валидацией: вместо неё ссылки на почту и Telegram.
- Раздел B8 про «реалистичные» имена и цифры. Здесь только настоящие факты. Если данных не хватает, пиши `TODO` в конфиге и скрывай блок, а не придумывай.

Всё остальное из `SKILL.md` обязательно: шрифты, шкала размеров, отступы, радиусы, фоны, hero, иконки, motion, состояния, ship requirements, блок tagline reveal.

## 3. Технические требования

- Чистый статический сайт: HTML, JS без фреймворков, Tailwind. Стили собери Tailwind CLI в `css/styles.css` и закоммить готовый файл. Никакого Tailwind CDN в продакшене.
- Должен работать на GitHub Pages из ветки `main`, папка `/` (без GitHub Actions). Добавь пустой `.nojekyll`.
- Все пути относительные, чтобы сайт открывался и на `username.github.io`, и на своём домене.
- Файлы: `index.html`, `privacy.html`, `404.html`, `data/projects.json`, `data/site.json`, `css/`, `js/`, `assets/`, `favicon`, `robots.txt`, `sitemap.xml`.
- Шрифт подключай локально (woff2 в `assets/fonts`), без Google Fonts: у части российских пользователей они грузятся плохо.
- Язык страницы: русский (`<html lang="ru">`). Все тексты вынеси в `data/site.json`, чтобы потом добавить английскую версию без переписывания вёрстки.
- Домен: `CNAME` не создавай, пока я не назову домен. Неверный `CNAME` ломает публикацию. Адрес сайта (`SITE_URL`) держи в одном месте и от него считай canonical, og:url и sitemap.

## 5. Структура страницы

Тип макета по `SKILL.md`: A (классический hero плюс секции), в сокращённом виде.

1. **Навигация.** Плавающая капсула по B7: полупрозрачная, с размытием, по центру, не прижата к верху. Пункты: Проекты, Обо мне, Контакты. На мобильном меню открывается во всю высоту, пункты появляются по очереди (шаг 60 мс, потолок 400 мс). Текущий раздел подсвечен.
2. **Hero.** Заголовок, подзаголовок, одна кнопка «Смотреть проекты», одна строка доказательства (только факты: например «2 приложения в Google Play и RuStore, 1 сайт»), визуал справа или снизу: сетка из иконок и экранов моих приложений.
3. **Проекты.** Три группы: Приложения, Сайты, Игры. Карточка: иконка, название, одна строка сути, платформа, кнопки. Для приложений на карточке один экран приложения.
4. **Tagline reveal (обязательный блок B11).** Две или три строки крупным текстом про то, что я делаю, слова загораются по одному при прокрутке. Черновик, правь по вкусу: «Делаю небольшие приложения и сайты, которыми приятно пользоваться каждый день. От идеи до карточки в магазине». Следи за словами из списка запрещённых в B8.
5. **Обо мне.** Короткий абзац: независимый разработчик, выпускаю приложения и сайты, публикую в Google Play и RuStore. Только то, что есть в этом ТЗ. Остальное через `TODO` в `site.json`.
6. **Контакты и подвал.** Почта и Telegram из `site.json` (пустые поля скрываются), ссылка на политику конфиденциальности, год. Блок контактов без формы.

Имя на сайте: бери из `site.json` (`name`). Стартовое значение «Dencherk» взято из идентификатора пакета приложений, я поправлю на настоящее.

## 6. Визуальная система (кратко, полные значения в `SKILL.md` Part B)

- Тема тёмная. Фоны только из списка B4: `#000000`, `#181818`, `#1F1F1F`, `#272727`, `#313131`, `#131209`. Страница `#181818`, карточки `#1F1F1F`, рамки `#313131`. Текст `#FFFFFF`, второстепенный `#9B9B9B`. Градиентов в фонах нет.
- Заголовок hero: градиент по тексту слева направо `#FFFFFF` → `#9B9B9B`. Ширина заголовка и подзаголовка не больше 680px, переносы строк по смыслу.
- Шрифт один: **Manrope**, начертания не тяжелее semibold или bold, без курсива. Из разрешённых шрифтов Manrope надёжно закрывает кириллицу. Geist и Poppins используй, только если подтвердишь поддержку кириллицы. Два шрифта не смешивать.
- Размеры текста только по шкале Tailwind (`text-xs` … `text-9xl`). Кнопки: основные `text-base` semibold, мелкие в шапке `text-sm` semibold. Основная кнопка: отступы 8px по вертикали и 12px по горизонтали.
- Отступы только из таблицы B2 (2, 4, 8, 12, 16, 24, 32, 40, 48, 64, 80, 96 px). В Tailwind это `0.5, 1, 2, 3, 4, 6, 8, 10, 12, 16, 20, 24`. Значения вроде `p-5` и `gap-7` нельзя.
- Радиусы только Tailwind. Вложенные формы по формуле: внутренний радиус = внешний − зазор, если зазор меньше 32px и результат больше 2.
- Рамка карточки только вокруг целиком или никакой.
- Иконки: Phosphor. Material не использовать.
- Копирайт: нет дефиса «-» в видимых текстах, заголовках и подписях (переписывай фразу, длинное тире «—» можно). Заголовки и кнопки с заглавной только в начале предложения. Для заголовков `text-wrap: balance`, для абзацев `text-wrap: pretty`, чтобы не оставалось одного слова на последней строке. Подтверждения и ошибки спокойные, без восклицательных знаков.
- Состояния каждого интерактивного элемента: hover, active (`scale(0.98)`), видимое кольцо фокуса. Ссылок-пустышек `#` нет.

## 7. Анимация

Базовая кривая везде `cubic-bezier(0.22, 1, 0.36, 1)`, 500 мс на положение, 300 мс на цвет и прозрачность. Анимируем только `transform` и `opacity`.

Из `SKILL_motion.md` берём только веб правила, всё про Figma, слои, MP4 и GIF пропускаем:

- Секции появляются один раз при входе в экран (IntersectionObserver, порог около 30%): подъём на 32px и проявление за 600–800 мс. Без `scroll` слушателей без троттлинга.
- Внутри секции карточки появляются по порядку чтения со сдвигом 80–90 мс.
- При конфликте с `SKILL.md` побеждает `SKILL.md`: например, блюр на входе не используем, потому что он не `transform` и не `opacity`.
- `prefers-reduced-motion: reduce`: всё сразу в конечном состоянии, движение заменено на смену прозрачности. Это касается и tagline reveal.
- Циклических анимаций внутри скриншотов в первой версии нет.

## 8. SEO и ship

- `<title>`, meta description, canonical, Open Graph и Twitter card. `og:image` 1200×630 (сделай простой статический вариант, я заменю).
- JSON-LD: `Person` для меня, `MobileApplication` для каждого приложения (название, операционная система Android, ссылки).
- Семантическая вёрстка: `nav`, `main`, `section`, `article`, `footer`. Ссылка «Перейти к содержимому» первой на странице. Alt на всех значимых картинках.
- Фавикон: простой знак из первой буквы имени, SVG и PNG.
- Кастомная `404.html` в стиле сайта со ссылкой на главную.
- `privacy.html`: коротко и честно, что сайт не использует cookies и не собирает персональные данные, ссылки на магазины ведут на сторонние сайты. Ссылка на неё в подвале.
- `robots.txt` и `sitemap.xml`, индексация включена.
- Цели: Lighthouse не ниже 95 по Performance, Accessibility, Best Practices, SEO на мобильном профиле. Нет горизонтальной прокрутки от 360px.
